# Colchones Segunda Itzel

Landing page for a used-mattress store in Mexicali, Baja California.
Vite + React 18 + Tailwind 4. Originally exported from Figma Make.

Pipeline: **Figma → Claude (SEO) → GitHub → cPanel**

Every push to `main` triggers a build in GitHub Actions and uploads the
compiled `dist/` to cPanel over FTPS. There is no manual uploading.

## Local development

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # writes dist/
npm run preview  # serve dist/ locally, exactly as cPanel will
```

`dist/` is generated by CI and is deliberately not committed.

## Before the site goes live

`index.html` currently carries `<meta name="robots" content="noindex, nofollow">`,
left over from the Figma Make export. **Google will not index the site until that
line is removed.** The SEO pass also still needs a meta description, a canonical
URL, Open Graph tags, `robots.txt`, `sitemap.xml`, and LocalBusiness JSON-LD —
all of which need the final domain before they can be written.

## Deployment setup

### 1. cPanel side

1. **Domains** → add the domain (or use the primary one). Note the document
   root it reports, usually `public_html`.
2. **SSL/TLS Status** → run *AutoSSL*. Do this **before** the first deploy —
   `.htaccess` forces HTTPS, so deploying first would redirect to a certificate
   that does not exist yet.
3. **FTP Accounts** → create an account scoped to the document root.
   Keep the password; cPanel will not show it again.
4. Note the FTP server hostname (`ftp.yourdomain.com`, or the server hostname
   shown in the right sidebar if DNS has not propagated).

### 2. GitHub side

**Settings → Secrets and variables → Actions → New repository secret**, three secrets:

| Secret | Value | Example |
| --- | --- | --- |
| `FTP_SERVER` | FTP hostname, no `ftp://` | `ftp.colchonesitzel.com` |
| `FTP_USERNAME` | Full FTP username | `deploy@colchonesitzel.com` |
| `FTP_PASSWORD` | That account's password | |
| `FTP_SERVER_DIR` | Target directory, **trailing slash required** | `public_html/` |

`FTP_SERVER_DIR` is relative to where the FTP account lands. If the account is
already scoped to the document root, the correct value is `./`.

### 3. Deploy

Push to `main`, or run the workflow manually from the **Actions** tab.
The first run uploads everything; later runs upload only what changed.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Blank white page | Assets 404ing — `FTP_SERVER_DIR` points at the wrong folder |
| `530 Login incorrect` | Username needs the full `user@domain` form |
| Redirect loop | AutoSSL has not issued a certificate yet |
| Old version still showing | Browser cache; `.htaccess` sets `no-cache` on HTML after the first deploy |
| Deploy uploads everything each time | `.ftp-deploy-sync-state.json` was deleted from the server |

If the host blocks FTP entirely, `.cpanel.yml` is a starting point for
deploying through cPanel's Git Version Control instead.
